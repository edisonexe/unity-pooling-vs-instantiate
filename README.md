# Unity Object Pooling Benchmark (Stress-Test Simulation)

![Unity Version](https://img.shields.io/badge/Unity-6.3_LTS-blue?logo=unity)
![Architecture](https://img.shields.io/badge/Architecture-SOLID_%2F_MVP_%2F_Object_Pool-orange?style=flat-square)
![Frameworks](https://img.shields.io/badge/Frameworks-Zenject-green)

Высокопроизводительный бенчмарк для демонстрации и сравнения эффективности кастомного паттерна **Object Pool** против классического подхода **Instantiate / Destroy** в среде Unity под экстремальной нагрузкой (3000+ активных объектов одновременно).

Посмотреть демо прямо в браузере можно здесь: [тык](https://ray-rid.itch.io/pooling-benchmark)

## Технический стек

* **Версия Unity**: 6000.0.31f1
* **Платформы**: Windows, WebGL
* **Фреймворки**: Zenject (Extenject)

## Управление и навигация

* Чтобы начать тест, нажмите на кнопку **Start Benchmark**.
* Чтобы переключить режим тестирования (**Naive / Pool**), нажмите на кнопку **Change Mode** в панели управления справа.
* Слева выводится панель статистики, отображающая FPS, количество активных объектов и метрики утилизации пула в реальном времени.

## Архитектура и паттерны

Проект написан по принципам SOLID со слабой связанностью компонентов, без использования тяжелых обновлений в Update для каждого объекта.

### Инструменты и паттерны
* **Zenject**: отвечает за биндинги, граф зависимостей и внедрение их в системы.
* **MVP**: используется для реализации UI. Презентеры написаны на чистом C#, они управляют логикой окон и подписками, оставляя View пассивными.
* **Object Pool**: реализован на основе очередей для переиспользования игровых объектов без лишней сборки мусора (Zero-GC).
* **Simulation Facades**: выступают изолированными шлюзами для внешних систем, полностью координируя связывание, инициализацию и деактивацию POCO-данных и MonoBehaviour-представлений сущностей.
* **Spatial Grid**: двумерная сетка для локальной сортировки целей, которая группирует объекты по ячейкам, позволяя оптимизировать алгоритмы поиска и выборки.

### Оптимизация логики
* Поведение целей и пуль вынесено из MonoBehaviour-скриптов в отдельные менеджеры, которые обрабатывают объекты централизованно.

## Результаты и итоги бенчмарка
Наивный подход с регулярным вызовом `Instantiate` и `Destroy` создавал непрерывный поток тяжелых рантайм-аллокаций памяти под тысячи генерируемых объектов каждый кадр. В рантайме это приводило к регулярным микрофризам в моменты автоматической сборки мусора, из-за чего средний FPS падал, а график времени кадра становился нестабильным.

Переход на паттерн `Object Pool` полностью ликвидировал аллокации от пересоздания сущностей. За счет полного устранения оверхеда на выделение памяти и исключения фризов от Garbage Collector время кадра стабилизировалось, что **обеспечило прирост среднего FPS примерно на 20-30%** в условиях экстремального теста. Симуляция при пиковой нагрузке **стала работать предсказуемо, стабильно и плавно**.
